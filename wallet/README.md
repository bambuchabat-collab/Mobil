# Генератор seed-фраз (BIP-39 / BIP-32)

Генерация и проверка seed-фраз для кошельков, которые вы создаёте сами.
Чистый Python 3.9+, только стандартная библиотека — ничего не ставится и ничего
не уходит в сеть.

## Что это НЕ делает

Это не инструмент восстановления. Подобрать seed-фразу к существующему
кошельку нельзя — и дело не в мощности железа: в самой короткой фразе 128 бит
энтропии, то есть 2¹²⁸ вариантов. Если перебирать триллион фраз в секунду на
триллионе машин, до заметной вероятности успеха уйдёт во много раз больше
времени, чем существует Вселенная. Единственная реальная защита кошелька — это
и есть невозможность такого перебора.

Если фраза утеряна частично (известен порядок, но забыто одно-два слова),
восстановление математически возможно, но это уже другая задача — и делать её
имеет смысл только для своего кошелька.

## Файлы

| Файл | Назначение |
| --- | --- |
| `bip39.py` | Генерация, проверка и нормализация фраз; вывод 64-байтного seed |
| `bip32.py` | Расширенные ключи (xprv/xpub) и деривация по путям, secp256k1 |
| `ripemd160.py` | RIPEMD-160 на чистом Python — фолбэк, см. ниже |
| `english.txt` | Официальный английский словарь BIP-39, 2048 слов |
| `tests/test_vectors.py` | Официальные тест-векторы BIP-39 и BIP-32 |

## Использование

Сгенерировать фразу (по умолчанию 24 слова — 256 бит энтропии):

```bash
python3 bip39.py new
python3 bip39.py new --words 12 --count 5
```

Проверить фразу — слова и контрольную сумму:

```bash
python3 bip39.py check "legal winner thank year wave sausage worth useful legal winner thank yellow"
# VALID
# words:      12
# entropy:    128 bits
```

Ошибка в одном слове ловится контрольной суммой: у случайного набора из 12
валидных слов шанс пройти проверку — 1 к 16.

Получить seed и расширенные ключи:

```bash
python3 bip39.py seed "your phrase here"
python3 bip32.py "your phrase here" --path "m/44'/0'/0'/0/0"
python3 bip32.py "your phrase here" --path "m/44'/60'/0'/0/0" --public
```

Фразу можно передать и через stdin, чтобы она не попала в историю shell:

```bash
python3 bip32.py --path "m/44'/60'/0'/0/0" < phrase.txt
```

Флаг `--public` печатает только xpub и fingerprint, без seed и xprv — такой
вывод можно показывать кому угодно и использовать для watch-only режима.

Как модуль:

```python
import bip39, bip32

phrase = bip39.generate(24)
key = bip32.ExtendedKey.from_seed(bip39.to_seed(phrase)).derive("m/44'/60'/0'/0/0")
print(key.serialize())          # xprv...
print(key.neutered().serialize())  # xpub...
```

## Проверка корректности

```bash
python3 tests/test_vectors.py
```

34 теста: все 24 английских вектора BIP-39 (энтропия → фраза → seed → xprv) и
все 4 вектора BIP-32 (17 путей деривации), включая те два, что специально ловят
потерю ведущих нулей в base58. Словарь сверяется по SHA-256 при каждой загрузке —
одно изменённое слово давало бы фразы, которые не прочитает ни один другой
кошелёк.

Совпадение с векторами означает, что фразы отсюда понимает любой BIP-39
кошелёк — Ledger, Trezor, Metamask, Sparrow.

BIP-32 требует RIPEMD-160, а OpenSSL 3 убрал его в legacy-провайдер, из-за чего
`hashlib.new("ripemd160")` падает на многих современных системах. Поэтому есть
`ripemd160.py`: `hashlib` используется, если работает, иначе чистый Python.
Векторы BIP-32 в тестах прогоняются обоими путями, так что фолбэк даёт те же
ключи, а не тихо другие.

## Про passphrase (25-е слово)

`--passphrase` даёт от той же фразы совершенно другой набор кошельков.
Неправильную passphrase невозможно отличить от правильной: каждая открывает
валидный, но пустой кошелёк. Забыли passphrase — потеряли деньги, и ничего
восстановить будет нельзя.

## Если фраза для реальных денег

- Генерируйте на машине без сети, лучше с загрузочной флешки, и не на сервере.
  Здесь фраза печатается в stdout — она осядет в логах, в истории терминала и в
  буфере обмена.
- Записывайте на бумагу или металл, не в фотографии, заметки, менеджер паролей
  или облако. Скриншот — самый частый способ потерять кошелёк.
- Проверьте фразу до того, как переводить на неё средства: введите её в
  кошелёк, где будете пользоваться, и сверьте адрес первого аккаунта.
- Регистр и лишние пробелы влияют на результат — храните фразу в нижнем
  регистре, как её печатает `check` в строке `canonical`.
- Для крупных сумм аппаратный кошелёк лучше любого скрипта: там ключ
  генерируется в защищённом элементе и не покидает устройство.

Реализация secp256k1 здесь простая и не защищена от атак по сторонним каналам.
Для генерации и просмотра ключей на своей машине этого достаточно, для подписи
транзакций на чужом или общем хосте — нет.
